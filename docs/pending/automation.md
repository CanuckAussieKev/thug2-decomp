# automation - a test-automation channel in the DLL (commands in, status out)

Agent "automation" (tooling, not a decomp batch). The user's goal: navigating the menus in automated tests fast and
reliably - posted WM_KEYDOWN keys after a fixed 35-60 s wait got dropped, and only a screenshot told where the game was.

## What it is (NOT ORIGINAL code: src/game/front/automation.{h,cpp}, automation_tables.inc)
- `[features] automation=1` (default 0; make_workspace.ps1 turns it on in the workspaces; **never on in the main
  install**). Once a frame (MouseMenus::Update, the front end's input logic - also paused and in levels) the DLL reads
  the lines added to `<game folder>\thug2-decomp-commands.txt` and runs them in order, logging each with its result, and
  rewrites `<game folder>\thug2-decomp-status.json` when anything in it changes (or every 30 frames).
- Commands: `run <script> [name=value | flag]...` (spawned), `choose <id> [s]` (the item's menu stepped there with the
  same pad events the mouse code sends, then pad_choose; waits for the item, its menu taking pad events, menu input
  unblocked and no loading screen; a menu id chooses its selected item; a non-menu element gets pad_choose itself),
  `focus <id> [s]`, `press <button> [frames]` (port 0's control data in Sio's ProcessSdlDevice - no window messages;
  waits up to 5 s for the menus to take pad events), `wait <frames>`, `waitfor ready | frontend | ingame | level <name>
  | menu <id> | focus <id> [s]`, `level <name>` (Front::StartLevel::Load, as -level), `echo <text>`, `quit` (SDL_QUIT).
  A parse error, refusal or timeout skips the rest of the batch (counted as done, so tools stop waiting).
- Status: frames, ready (latched: the main menu has taken pad events for a second), main_menu, where, paused, loading,
  level (the skate module's +0x378 load script), game_mode (0x005532A0), focus (the element manager's controller-0
  focus list), selected, lines_read / lines_done / queued, current, last, result, errors, refusals.
- `-run <script>` on the command line: run once the main menu is up (with or without the channel; same deny-list).
- Safety: `run` refuses every script of the game's network files (net.qb, netoptions.qb, netmenu.qb, onlinestats.qb,
  net_vault_menu.qb, pager_menu.qb, levels\mainmenu\mainmenu_net.qb) and hand-named gateways (change_gamemode_net,
  select_network_play_multi, select_internet_play...), and any script or parameter whose name has an online word;
  `choose` / `focus` refuse denied ids (menu_net, mm_net_play, mm_multi_play, the net files' own ids...) and items whose
  event handlers (or their menus' pad_choose / pad_start handlers) run or name a denied script anywhere in their
  parameters; `press` of a non-direction refuses while such an item is focused; while the game is online / in a network
  game / in a net* game mode only wait / echo / quit run. 588 scripts, 234 ids (generated by
  tools/game/make_automation_tables.py from the game's loose scripts).

## Small edits to shared files
- src/game/front/mouse_menus.{h,cpp}: calls Front::Automation::Update; two public wrappers (MenuGetsPadEvents,
  SendMenuPadEvent) over its private MenuTakesPadEvents / SendPadEvent.
- src/game/sio/sdl_input.cpp: ProcessSdlDevice adds Front::Automation::AddPadButtons before inverting the bits.
- src/game/front/start_level.{h,cpp}: the level start factored into a public `Load(name, why)`; **-level fixed**: the
  command line is now read while the DLL loads - the game's own parsing cut the buffer to `"...THUG2.exe" -level` before
  StartLevel read it (seen with the stock THUG2.exe: -level did nothing; -run had the same problem).
- src/game/sys/sdl_window.cpp: with the channel on, losing the focus doesn't clear the active flag (0x007CCBE4), so the
  main loop keeps drawing in the background and PrintWindow pictures show the current frame (before: the last frame
  drawn while focused - often the start-up loading logo, also for the old -Keys runs).
- CMakeLists.txt: automation.cpp, selftests_automation.cpp.
- tools/game: run_game.ps1 (-Commands, -WaitReady, -Run; deletes the command file before and after a run),
  game_cmd.ps1 (new), automation.ps1 (new, shared helpers), make_workspace.ps1 (automation=1; the channel's files not
  mirrored), make_automation_tables.py (new); README; docs/agent-rules.md (prefer commands over keys).
