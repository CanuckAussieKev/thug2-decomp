# Create 100% CAS (feature agent "cas100", 2026-10-19)

The user's request: a menu option that gives a skater with maxed stats and a 100% complete story. Not a decomp batch,
so there's nothing to fold into decomp-progress.md.

## What it is
- **Where:** in the front end's GAME OPTIONS, after GAME PROGRESS: **CREATE 100% CAS**. It asks first with a
  Yes / No dialog ("This replaces your current Story Mode progress ... Save with SAVE GAME afterwards"). When it's
  done it says so, and OK goes back to GAME OPTIONS. Nothing is saved automatically: the player saves with SAVE GAME.
- **Script** (tools/menu_level/career_complete.py writes it into the data overlay's
  `levels\mainmenu\mainmenu_options.qb`). It uses the game's own scripts and commands wherever they exist:
  - reset_gamemode in story mode, the same as START NEW STORY MODE (every profile's stats and tricks, the career, the
    goal manager's career and the story flags reset). Difficulty is Normal (GoalManager_SetDifficultyLevel 1,
    skater:StatsManager_ReInit).
  - Every CHAPTER_INFO chapter is CHAPTER_COMPLETE, with its intro and outro seen and its cutscenes'
    VIEWED_CUTSCENE flags set. Its level is unlocked and seen in the level select, as UnlockNextChapter does.
  - What the levels' stories set along the way, read from the level scripts: 25 flags (GUEST_FOUND_, PRO_FOUND_,
    SKATER_UNLOCKED_, TRICK_UNLOCKED_) and 7 special tricks (AwardNewSpecialTrickToProfile all_profiles).
  - SetRewardFlagArray with story_game_complete_rewards on Easy, Normal and Sick (GAME_COMPLETED_*, the PRO SKATER
    level, the WDT movie, the secret skaters and ped groups) and with story_goal_complete_rewards (CAREER_GOALS_COMPLETE,
    the pro bails 2 movie, ped group 6). CAREER_SEEN_GAME_COMPLETE_MESSAGE / _GOAL_ are set so the game doesn't
    announce these again, and CAREER_STARTED is set.
  - The current chapter is set to 8, the one GoToNextChapterPostCutscene goes back to after the last chapter.
  - The created skater (profile `custom`) gets every stat_names stat at 10 (SetSkaterProfileInfoByName). Its
    appearance is left as it was.
- **C++** (src/game/front/career_complete.*, NOT ORIGINAL, `[features] create_100_cas=0` hides the item and refuses
  the command). It does the things no script command can do:
  - `Career100_Available`: whether the item is shown.
  - `Career100_Apply levels=[{level points total goals=[...]}]`:
    - Sets each story level's points and potential in the career, changing the totals the same way AddCash and
      SetLevelAmount do. The result is 11000 / 11000, the game's own threshold for "all story goals".
    - Writes every story goal as beaten into the goal manager's store of goals that aren't loaded (+0x14:
      `{levelNum unlocked hasBeaten record career}`, the way a goal's save writes it). GoalManager_LevelLoad then
      loads the level's goals as beaten.
    - Marks the local skater's 70 story stat challenges done (stats manager component 0x4FF8DAC6, status 1), so the
      stats menu allows 10 / 10.
- **Goal names** are worked out the way GoalManager_CreateGoalName makes them: `<level prefix>_goal_<type><version>`.
  The source is each story level's `<prefix>_Goals` script (its story part, after the classic / net `if`) and the
  chapters' goals_script, followed through the AddGoal_* calls. That gives 191 goals: TR 37, BO 24, BA 24, BE 24,
  AU 26, NO 25, ST 31. Their reward points add up exactly to each level's last level_total_points (TR 0 of 1000,
  which is the game's own: training goals give no points).

## Fix: the free-skate level select (agent "cas100fix", 2026-10-20)
The user's report: after CREATE 100% CAS, HIGH SCORE / FREE SKATE's level select showed a row of "?" (locked) signs.

**Root cause** (found in the game, THUG2-3, with temporary logging in CSkaterCareer::Set/UnSet/GetGlobalFlag and the
automation channel): the story part was right all along - after cas100_apply the free-skate list reads LEVEL_SEEN_TR
... LEVEL_SEEN_SE (214-221) = 1 from the one career (skate +0x20; no other career, nothing clears them afterwards),
and BARCELONA ... SKATOPIA and PRO SKATER are selectable. The "?" signs are the seven other THUG2 levels: outside
story / classic mode the level select goes by the LEVEL_SEEN_ flags (level_select_should_use_seen_flags) and then
drops their hide_when_locked, so SCHOOL, PHILADELPHIA, DOWNHILL JAM, LOS ANGELES, CANADA, AIRPORT and THE TRIANGLE
(LEVEL_SEEN_SC ... _AP, _SE2 = 222-231: 0) show as locked "??????????" signs. No story script sets those: only classic
mode's progress does (CheckClassicAdvancementStatus, classic_mode_menu.qb).

**Fix** (tools/menu_level/career_complete.py): cas100_apply also runs `cas100_classic_levels`, which does what
CheckClassicAdvancementStatus does once each bracket's goals are done: for every entry of
level_select_menu_classic_level_info its bracket flag (LEVEL_BRACKET_UNLOCKED_1..9) and its LEVEL_SEEN_ flag, then
the last bracket's reward - GAME_CLASSIC_UNLOCKED_SE2, LEVEL_SEEN_SE2 and SetClassicTotalGoals 140 (the career's
classic goal total: 130 -> 140 with THE TRIANGLE). Classic mode itself isn't completed (its goals stay unbeaten, no
GAME_COMPLETED_CLASSIC_* flags - SAVE shows "Classic: 0 of 140 goals"); that would need every classic goal of all
16 levels beaten through the goal manager like the story ones - not done, could be added if wanted. The two dialogs
now say all 16 levels are opened, classic mode's too. No C++ change.

**Tested in the game (THUG2-3, automation channel):** GAME OPTIONS > CREATE 100% CAS > Yes > OK, back, HIGH SCORE /
FREE SKATE, skater, level select: no "?" signs; stepping right through the THUG2 list: SKATE SHOP, TEST LEVEL,
BOSTON, BARCELONA, BERLIN, AUSTRALIA, NEW ORLEANS, SKATOPIA, PRO SKATER, THE TRIANGLE, SCHOOL, PHILADELPHIA, DOWNHILL
JAM, LOS ANGELES, CANADA, AIRPORT, CREATED PARK, TRAINING - every one selectable. Then SAVE GAME (overwrote the
workspace's save, restored from a backup afterwards), quit, restart, LOAD GAME: the same 16 levels open in the free-skate
level select. (A finding on the way: with posted keys and no automation the game stops drawing in the background, so
PrintWindow pictures stay on the loading screen.)

## Classic Mode, gaps and unlockables (agent "cas100classic", 2026-10-20) - NOT run in the game yet
The user's request: CREATE 100% CAS also completes Classic Mode (the save screen said "Classic: 0 of 140 goals"),
every gap (GAME PROGRESS, the all-gaps reward), and leaves nothing locked that playing story or classic mode
unlocks. No game was launched (offline only); everything in the game below is untested.

### Where the game keeps classic progress (Ghidra, read-only snapshot copy)
- **The goal win** 0x005576D0 (a goal's win, after its success): in story mode (GameModeEquals 0x1DED1EA4) it adds
  the goal's reward points (AddCash 0x005845C0); in classic mode (`is_classic`, 0x5A2C589A) it calls
  **IncrementCounter 0x00584620** - the current level's classic counter (career +0x5DC + level, 18 levels) and the
  total (+0x5EE). These are the only callers of either. The career's goal bits (200-255 for classic, as Reset's
  0x4C10DE52 part clears) aren't touched by goal wins: only the script commands SetGoal / GetGoal (0x005AECC0 /
  0x005AED40) and 0x005619E0 use them, and no script does. So classic progress is the counters plus the goals'
  own state.
- **The goals' state**: a goal's save 0x00554770 writes levelNum, unlocked, 0x2206B1E7, hasBeaten, the record, and
  a bare name - `classic` (0x4C10DE52) if the goal has `classic_mode_goal` (0x32D771EE), else `career`. The goal
  manager keeps these for goals that aren't loaded in its +0x14 structure by goal name (the same store as the story
  goals); GoalManager_LevelLoad 0x00558A00 hands each to the loaded goal of that name (vtable +0x18).
  GoalManager_ResetCareer <mode> (0x00557E70) drops the store's entries whose structure has the bare name <mode> -
  so the tag decides which reset clears a goal.
- **Counts**: GetClassicLevelGoalCount 0x005AEAE0 - `classic_goal_count` = the level's counter (0x00584640), with
  get_total `total_goals_complete` = +0x5EE and `total_goals_possible` = +0x5EF (SetClassicTotalGoals 0x005AEB80 -
  0x00584650; 0x82 = 130 after a reset, 140 once THE TRIANGLE opens). The level select's "x/10", GAME PROGRESS's
  CLASSIC MODE GOALS COMPLETE and CheckClassicAdvancementStatus all read these.
- **The save**: CSkaterCareer::WriteToStructure / ReadFromStructure (src/game/skate/career.cpp) keep the counters
  (0xE888DD02), their total (0x6C1A5E39) and +0x5EF (0x7A6BF912); the goal manager's store is saved with the goal
  manager (the story goals' entries already survive SAVE / LOAD the same way - cas100fix's test).
- **Starting a new classic mode** (reset_gamemode in classic mode, mainmenu_scripts.qb): UnsetGlobalFlag
  CLASSIC_STARTED, CareerReset classic (counters, goal / flag bits 200-255 of the first 18 levels, the total,
  +0x5EF = 0x82), GoalManager_ResetCareer classic (the store's `classic` goals), and CLASSIC_CLEAR_GLOBAL_FLAGS
  (brackets 2-9, GAME_CLASSIC_UNLOCKED_SE2, the two CLASSIC_SEEN_ flags). The rewards (GAME_COMPLETED_CLASSIC_*,
  skaters, movies) stay. So NEW CLASSIC MODE after CREATE 100% CAS wipes the classic part, as it would for a player;
  CONTINUE CLASSIC MODE needs CLASSIC_STARTED (create_gamemode_options_menu's mode_flag), which CAS now sets.
- **Difficulty**: GoalManager_SetDifficultyLevel / GetDifficultyLevel (0x0055B1A0 / 0x0055B1F0) keep one value per
  game mode (stored under the mode's name; 1 when never set). CAS sets story Normal (1) and leaves classic's as it
  was (unset: 1 = Sick in classic's numbering - the classic menu offers Normal 0 / Sick 1). Both classic complete
  flags are set anyway.

### Classic goal names
GoalManager_CreateGoalName 0x00559980: `<level prefix>` + `_classic` (in classic mode or with classic_mode_goal) +
`_goal_` + goal_type - the same AddGoal_* goal types as the story ones (career_complete.goal_types). The goals are
each classic level's <prefix>_Goals script's `if ((GameModeEquals is_classic) or (InNetGame))` block. NeverScript
can't decompile CA_scripts.qb ("Unexpected byte in switch body"), so tools/menu_level/qb_walk.py reads the compiled
tokens (classic_goal_calls); for the 13 levels NeverScript does read, its result matched a text-based reading.
Exactly 10 per level for the 14 classic levels of level_select_menu_classic_level_info (BA AU ST BE AP SC DJ NO TR BO
CA PH LA SE2) = 140, matching ProcessGoalRewards' 140 and THE TRIANGLE's SetClassicTotalGoals 140. E.g.
BA_classic_goal_HighScore / ProScore / SickScore / HIghCombo / Skate / Combo / Collect / SecretTape / GAps / GAps2.

### Gaps
- **How a level's checklist is made**: CFunc_ParseNodeArray 0x005A34E0 (every level load) calls
  CGapChecklist::Build 0x00578AC0 on the skate module's checklist (the career's m_gaps[current level]) unless
  ParseNodeArrayIgnoreGaps is set: SkateScript::ForEachNodeScriptCall 0x0045CCA0 walks every node's TriggerScript
  through the scripts it calls (ForEachScriptCall 0x0045C950: depth 5, both ways of every `if`, SetEventHandler's
  scr= and EndGap's gapscript= followed, the script's first line - its default parameters - skipped) and each EndGap
  with a score= and a non-empty text= is AddGap(text, 0, score) - an existing gap of that name and score is only
  marked in the level, so landings survive. Landing: GotGap / AwardPendingGaps 0x005796C0; right after that,
  0x00511C30 runs ProcessAllGapsReward (0x927DAA70) when CSkaterCareer::AllGapsGot 0x00584BC0 holds: every level of
  `levels_with_gaps` (0xEB1A4BC9, Levels.qb: TR BO BA BE AU NO ST SE SE2 SC PH DJ LA CA AP) visited (career +0x690,
  set by StartLevel - nothing else reads it) and every gap of its checklist landed. The save keeps each checklist
  (built flag, every gap's name, count and score, and a landed gap's skater start position / direction), and the
  visited flags. CareerReset doesn't reset gaps (ResetPart: Reset(false, ...)), so a new story keeps them.
- **Built without loading the levels**: qb_walk.gap_list does Build's walk offline on the compiled .qb files
  (qb_scripts.prx's scripts plus the level's <prefix>_scripts.prx: its node array <prefix>_NodeArray and scripts),
  with ParseArguments' parameter passing (<param>, <...>, structures merged). Without the game's function tables, a
  name that isn't a script counts as a C / member function where a statement starts (and its statement is skipped,
  as the game does for every function but EndGap and SetEventHandler) and is stepped over inside a statement.
  Result: TR 25, BO 39, BA 32, BE 48, AU 39, NO 36, ST 42, SE 31, SE2 22, SC 47, PH 53, DJ 18, LA 73, CA 63, AP 35 =
  603 gaps, all plain ASCII names, no name with two scores.
- **What CAS writes** (Career100_Apply gaps=): AddGap(name, 1, score) into each level's checklist (a gap already
  landed is left alone), positions set to the node that leads to the gap's EndGap (the gap menu's camera goes 80
  units above a landed gap's start position: with none it would sit at the origin facing straight up), any gap
  already in the checklist with no landing gets one, and the level marked visited. If the walk missed a gap, the
  level's next load adds it unlanded: GAME PROGRESS would then show e.g. 47 / 48 for that level - the reward is
  already given, so nothing else changes.
